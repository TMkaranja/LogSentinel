# LogSentinel Phase 1 — Complete Project Publication Scope Review

**Purpose:** file-by-file review of all 28 tracked paths classified HOLD in the Phase 1 source-publication manifest, for a proposed complete LogSentinel Phase 1 source repository.

**Disposition:** this is a read-only engineering and publication-scope recommendation, not authorization to stage, commit, push, publish, distribute, or a legal opinion. **The Windows GUI executable and ZIP remain HOLD — NOT CLEARED FOR DISTRIBUTION.** Making GUI source available, or publishing build recipes, does not clear any binary.

**Snapshot reviewed:** branch `main`, HEAD `3229b17`, `origin/main` `e5bcfd0`; 87 tracked paths. At review time, four tracked files were already modified (`.gitignore`, `README.md`, `docs/USAGE.md`, and `packaging/LogSentinel-GUI-Onedir.spec`); none was edited for this review. There were no staged paths. This report is a new file only.

## 1. Executive recommendation

For a **complete source project**, the CLI, the optional GUI implementation, its tests, authored assets, project map, and packaging recipes belong in the intended public source scope. The review therefore recommends source inclusion for five of the 28 reviewed paths: `PROJECTMAP.md`, `tests/test_gui_themes.py`, both GUI `.spec` files, and `packaging/gui_entry.py`, **after the specific documentation, provenance, and build-recipe checks identified below**. They are not binaries, and including their source would not authorize an executable release.

The 23 GUI image/icon files are genuinely used by the GUI and its packaging/tests. Their contents are locally self-contained and technically simple, but the source commit contains no per-file author/source/license record. Several outline icons are strongly similar to Lucide/Feather-style shapes; this is a provenance lead, not proof that a particular upstream file was copied. Therefore the defensible classification for those 23 files is **HOLD pending positive authorship/source and license/notice evidence**, not blanket exclusion. This HOLD prevents a fully reviewed GUI-inclusive source allowlist from being ready today. Record the actual source/original author and relevant terms; add correctly scoped attribution/license material if required; then include the assets and their test.

No reviewed path was found to contain an actual credential, user log, setting, or personal record. This finding is bounded by manual/content and pattern checks and is not a guarantee. Source history, Git authorship, syntactic cleanliness, signatures, version strings, and similarity to a known icon set do not by themselves establish copyright ownership or legal clearance.

### Classification interpretation

The 23 individual asset HOLDs are not a recommendation to omit GUI art from a complete source repository. The GUI source explicitly uses local assets and its test verifies their presence; the packaging recipes collect those same assets. HOLD means do not put them in the proposed public index until the provenance/notice question is resolved. If provenance establishes original project creation and owner rights, update the allowlist to INCLUDE with that evidence. If any exact SVG is from Lucide, note the official Lucide license has an ISC notice and enumerates Feather-derived icons under MIT; check the applicable versioned terms and whether each exact asset is covered. A resemblance or live documentation page is not a version-specific license election.

## 4. Findings by review theme

### GUI source, assets, tests, and optional dependencies

The 28 tracked HOLD set does not include GUI Python modules or most GUI tests; those were already proposed for INCLUDE. `tests/test_gui_themes.py` is the sole GUI test in this set. It has nine test methods: two asset-presence checks and seven Qt-dependent theme/rendering checks, which skip if PySide6 is absent. The SVG/ICO collection comprises 22 vectors plus one ICO. All vectors are local, theme-colored, and self-contained; no remote assets or active SVG content were found. Those facts make the assets operationally suitable source resources, but do not resolve their origin.

Preserve the GUI as optional PySide6 source: `pyproject.toml` does not install PySide6 as a runtime dependency. Keep GUI import isolation and CLI behavior unchanged. For the complete-project test workflow, include the theme test and assets together; do not stage or publish the theme test or packaging recipes as a partial GUI subset while their required assets are held. Document a separate GUI development/test environment rather than making PySide6 mandatory for the CLI.

### Project map and packaging

`PROJECTMAP.md` belongs in a maintained complete source repository, but its claims must be updated before publication. The README also lists `PROJECTMAP.md` in its project tree, so either include a refreshed map or separately reconcile that README entry.

All three packaging paths are first-party Python source required to reproduce/maintain the GUI build recipes. `packaging/gui_entry.py` is directly referenced by both specs. The specs explicitly locate and collect the 22 SVGs and ICO; the present asset HOLD is therefore a build-recipe dependency, not an unrelated ornament. The current onedir spec has a pre-existing worktree-only 64-line change removing exactly `Qt6Pdf.dll`, `qpdf.dll` and `opengl32sw.dll` and asserting required paths remain. The one-file recipe has the older Qt Virtual Keyboard exclusion and no same three exclusions. Review the difference and run controlled build verification before freezing the exact scope. Do not undo the user’s existing modification.

Neither spec is an installer, runtime, notice bundle, corresponding source, or end-user release instruction. Publishing a spec or producing a successful build must not be represented as release, legal or compatibility clearance.

### Samples and test fixtures

None of the 28 reviewed tracked HOLD paths is a sample log. `samples/access.log`, `samples/auth.log`, and `samples/firewall.log` were already in the manifest INCLUDE set and are described as synthetic; valid addresses use RFC 5737 documentation blocks, with the documented invalid `999.1.1.1` parser fixture. This review does not reclassify or claim a fresh content audit of every already-INCLUDE test/sample file.

### Licensing and notice corpus
